# Architecture

## Source layout

| Directory | Responsibility |
| --- | --- |
| `App/Sources/LlamaPad` | SwiftUI workspaces, model library, settings, telemetry and WebKit chat integration |
| `App/ChatUI` | Branding and theme applied to the pinned upstream chat UI |
| `App/Assets.xcassets`, `App/Artwork` | App icon and branding assets |
| `Core` | Configuration, device profiles, model metadata and telemetry value types |
| `Native/include` | C ABI and Swift module map |
| `Native/runtime.cpp` | Embedded HTTP server/RPC lifecycle, configuration and snapshots |
| `Native/platform.mm` | Apple memory, CPU, power, thermal and GPU capability reporting |
| `Native/host.cpp` | Optional macOS host for the native runtime |
| `vendor/llama.cpp` | Pinned llama.cpp, GGML backends, server, chat UI and bundled libraries |
| `patches` | Engine changes and source-archive build adjustments |
| `Scripts` | Source verification, build, packaging, signing and coordinator launch |

## Runtime

SwiftUI owns one native runtime through a C ABI. Start/stop operations and bounded snapshots keep inference work separate from the UI. Server mode constructs the embedded llama.cpp HTTP service. Node mode constructs a controlled GGML RPC worker with a Metal backend, allocation checks, cancellable connection lifecycle and counters.

The app polls snapshots to update histories. Telemetry does not add synchronization waits to measure the GPU; completed command-buffer handlers record elapsed intervals. Transport byte counters advance during transfers rather than waiting for a whole weight message. Thermal readings use the OS category because this app has no public sensor-temperature API.

The server's assets are built from the vendored Svelte source and embedded in the native library. WebKit loads the loopback server, applies the native authentication bridge and retains chat data for that server origin. The UI can also support browser clients according to upstream capabilities.

RPC model orchestration remains on the Mac. The coordinator assigns layers to devices, constructs execution graphs and reports token timings. Worker telemetry describes backend execution and transport, not token generation. The app requests service shutdown when backgrounded and disables automatic screen locking while active.

## Build graph

CMake combines the native bridge with server-context, llama, GGML, Metal, Accelerate, RPC and the embedded UI. Device static archives become `LlamaNative.xcframework`; Swift Package Manager links that binary target into the app generated by xtool. The root Swift package exposes the platform-independent Core module. The Mac coordinator builds from the same vendored engine using its CMake project.

The source archive excludes test targets and fixtures. It includes source needed by the application and engine, including upstream backends/tools outside the Apple runtime path. Their presence does not imply platform qualification.
